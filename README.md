## Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.
View - слой представления, отвечает за отображение данных на странице.
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события, используя методы как Моделей, так и Представлений.

## Базовый код

## Класс Component

Является базовым классом для всех компонентов интерфейса.

Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:
`constructor(container: HTMLElement)` - принимает ссылку на DOM-элемент, за отображение которого он отвечает.

Поля класса:
`container: HTMLElement` - поле для хранения корневого DOM-элемента компонента.

Методы класса:
`render(data?: Partial<T>): HTMLElement` - главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component`, будут реализованы сеттеры для полей с данными. Они будут вызываться в момент вызова `render` и записывать данные в необходимые DOM-элементы.
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`.

## Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:
`constructor(baseUrl: string, options: RequestInit = {})` - в конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:
`baseUrl: string` - базовый адрес сервера.
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы класса:
`get(uri: string): Promise<object>` - выполняет GET-запрос на переданный в параметрах эндпоинт и возвращает промис с объектом, которым ответил сервер.
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на эндпоинт, переданный как параметр при вызове метода. По умолчанию выполняется `POST`-запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.
`handleResponse(response: Response): Promise<object>` - защищенный метод, проверяющий ответ сервера на корректность и возвращающий объект с данными, полученными от сервера, или отклоненный промис в случае некорректного ответа.

## Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:
`_events: Map<string | RegExp, Set<Function>>` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярные выражения, значения - коллекции функций-обработчиков, которые будут вызваны при срабатывании события.

Методы класса:
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие. Принимает название события и функцию-обработчик.
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое событие с передачей в него данных из второго параметра.

## Данные

В приложении используются две основные сущности, описывающие данные: товар и покупатель.

Для описания способа оплаты используется тип `TPayment`:

```ts
type TPayment = 'card' | 'cash' | '';
```

Тип `TPayment` может принимать следующие значения:

* `card` - оплата онлайн;
* `cash` - оплата при получении;
* пустая строка - способ оплаты еще не выбран.

Интерфейс товара:

```ts
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

Интерфейс `IProduct` описывает данные товара, которые используются в каталоге, карточке подробного просмотра и корзине.

Поля интерфейса:
`id: string` - уникальный идентификатор товара.
`description: string` - подробное описание товара.
`image: string` - ссылка на изображение товара.
`title: string` - название товара.
`category: string` - категория товара.
`price: number | null` - стоимость товара. Может иметь значение `null`, если цена товара отсутствует.

Интерфейс покупателя:

```ts
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
```

Интерфейс `IBuyer` описывает данные покупателя, которые необходимы для оформления заказа.

Поля интерфейса:
`payment: TPayment` - выбранный способ оплаты.
`email: string` - электронная почта покупателя.
`phone: string` - номер телефона покупателя.
`address: string` - адрес доставки заказа.

Для описания объекта с ошибками валидации используется тип:

```ts
type TBuyerErrors = Partial<Record<keyof IBuyer, string>>;
```

Тип `TBuyerErrors` описывает объект, содержащий ошибки валидации данных покупателя. Ключами объекта являются названия полей интерфейса `IBuyer`, а значениями - тексты ошибок.

Если поле заполнено правильно, соответствующее свойство в объекте ошибок отсутствует.

Пример объекта с ошибками:

```ts
{
  payment: 'Не выбран способ оплаты',
  email: 'Укажите email'
}
```

В данном примере ошибки присутствуют в полях способа оплаты и электронной почты. Поля телефона и адреса заполнены правильно.

## Модели данных

Для хранения и работы с данными в приложении используются три класса:

* класс каталога товаров;
* класс корзины;
* класс покупателя.

Каждый класс имеет отдельную зону ответственности и работает только со своими данными.

## Класс ProductCatalog

Класс `ProductCatalog` отвечает за хранение массива всех товаров, полученных с сервера, а также за хранение товара, выбранного пользователем для подробного отображения.

Конструктор:
`constructor()` - конструктор не принимает параметров. При создании экземпляра класса массив товаров является пустым, а выбранный товар имеет значение `null`.

Поля класса:
`products: IProduct[]` - массив всех товаров, полученных с сервера.
`selectedProduct: IProduct | null` - товар, выбранный пользователем для подробного отображения. Если товар еще не выбран, поле содержит значение `null`.

Методы класса:
`setProducts(products: IProduct[]): void` - сохраняет переданный массив товаров в модели. Принимает параметр `products` типа `IProduct[]`. Метод ничего не возвращает.
`getProducts(): IProduct[]` - возвращает массив всех товаров, сохраненных в модели. Возвращаемое значение имеет тип `IProduct[]`.
`getProductById(id: string): IProduct | undefined` - принимает идентификатор товара `id` типа `string` и возвращает найденный товар типа `IProduct`. Если товар с таким идентификатором не найден, метод возвращает `undefined`.
`setSelectedProduct(product: IProduct): void` - принимает товар `product` типа `IProduct` и сохраняет его для подробного отображения. Метод ничего не возвращает.
`getSelectedProduct(): IProduct | null` - возвращает товар, выбранный для подробного отображения. Если товар еще не выбран, метод возвращает `null`.

## Класс Basket

Класс `Basket` отвечает за хранение и изменение массива товаров, которые пользователь добавил в корзину. Класс также позволяет получить количество товаров, вычислить их общую стоимость и проверить наличие определенного товара в корзине.

Конструктор:
`constructor()` - конструктор не принимает параметров. При создании экземпляра класса корзина содержит пустой массив товаров.

Поля класса:
`products: IProduct[]` - массив товаров, которые пользователь добавил в корзину.

Методы класса:
`getProducts(): IProduct[]` - возвращает массив товаров, находящихся в корзине. Возвращаемое значение имеет тип `IProduct[]`.
`addProduct(product: IProduct): void` - принимает товар `product` типа `IProduct` и добавляет его в массив корзины. Метод ничего не возвращает.
`removeProduct(product: IProduct): void` - принимает товар `product` типа `IProduct` и удаляет его из массива корзины. Метод ничего не возвращает.
`clear(): void` - удаляет все товары из корзины. Метод не принимает параметров и ничего не возвращает.
`getTotal(): number` - подсчитывает и возвращает общую стоимость всех товаров в корзине. Если цена товара равна `null`, при подсчете она считается равной нулю. Возвращаемое значение имеет тип `number`.
`getCount(): number` - возвращает количество товаров, находящихся в корзине. Возвращаемое значение имеет тип `number`.
`hasProduct(id: string): boolean` - принимает идентификатор товара `id` типа `string` и проверяет наличие товара в корзине. Возвращает `true`, если товар находится в корзине, и `false`, если товара в корзине нет.

## Класс Buyer

Класс `Buyer` отвечает за хранение, изменение, получение, очистку и валидацию данных покупателя, необходимых для оформления заказа.

Данные покупателя могут сохраняться частями. При сохранении одного поля значения остальных полей не удаляются и не изменяются.

Конструктор:
`constructor()` - конструктор не принимает параметров. При создании экземпляра класса все поля покупателя содержат пустые строки.

Поля класса:
`payment: TPayment` - выбранный способ оплаты.
`address: string` - адрес доставки заказа.
`email: string` - электронная почта покупателя.
`phone: string` - номер телефона покупателя.

Методы класса:
`setData(data: Partial<IBuyer>): void` - принимает объект `data` типа `Partial<IBuyer>` и сохраняет переданные данные покупателя в модели. Тип `Partial<IBuyer>` позволяет передать как все данные покупателя, так и только отдельные поля. Значения полей, которые не были переданы, остаются без изменений. Метод ничего не возвращает.
`getData(): IBuyer` - возвращает объект со всеми сохраненными данными покупателя. Возвращаемое значение имеет тип `IBuyer`.
`clear(): void` - очищает все данные покупателя и возвращает поля класса к начальным значениям. Метод не принимает параметров и ничего не возвращает.
`validate(): TBuyerErrors` - проверяет заполненность всех полей покупателя и возвращает объект с ошибками валидации типа `TBuyerErrors`.

Поле считается валидным, если оно не является пустым.

Если поле не заполнено, метод `validate` добавляет в объект ошибок свойство с названием этого поля и текстом ошибки.

Возможные сообщения об ошибках:

* `payment` - «Не выбран способ оплаты»;
* `address` - «Укажите адрес»;
* `email` - «Укажите email»;
* `phone` - «Укажите телефон».

Если все поля покупателя заполнены правильно, метод `validate` возвращает пустой объект.
## Слой коммуникации

Слой коммуникации отвечает за взаимодействие приложения с API сервера интернет-магазина.

Для работы с сервером используется класс `WebLarekApi`. Класс получает в конструктор объект, соответствующий интерфейсу `IApi`, и использует его методы `get` и `post`.

## Класс WebLarekApi

Класс `WebLarekApi` отвечает за получение списка товаров с сервера и отправку данных заказа на сервер.

Класс использует композицию: он не наследуется от класса `Api`, а получает объект для выполнения запросов через конструктор.

Конструктор:  
`constructor(api: IApi)` - принимает объект, соответствующий интерфейсу `IApi`, который используется для выполнения запросов к серверу.

Поля класса:  
`api: IApi` - объект коммуникационного слоя, с помощью которого выполняются GET- и POST-запросы.

Методы класса:  
`getProducts(): Promise<IProductsResponse>` - выполняет GET-запрос на эндпоинт `/product/` и возвращает промис с объектом, содержащим количество товаров и массив товаров.

`createOrder(order: IOrder): Promise<IOrderResult>` - принимает объект заказа `order` типа `IOrder`, выполняет POST-запрос на эндпоинт `/order/` и возвращает промис с результатом оформления заказа типа `IOrderResult`.
